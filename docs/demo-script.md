# 5 分钟 Demo 视频脚本

> 目标受众：**评委 / 投资人 / 同行**。在 5 分钟内让他们看到 **「这是真 Agent，不是聊天框」「在教育领域真有用」「技术有深度」** 三件事。

## 制作要点

- **录屏分辨率**：1920×1080，60 fps，关闭其他通知/标签页
- **窗口尺寸**：浏览器开 1440 宽，留 240 给 sidebar/trace panel 浮动
- **解说语速**：中文 240–280 字 / 分钟，要快但不破音
- **画面节奏**：每 8–12 秒换一个亮点画面，避免静止
- **B-roll**：在 LLM 等待时切到 AgentTracePanel（用户最爱的"AI 在干活"视觉证据）
- **字幕**：全程双行，**关键数字一定打到屏幕上**（TTFT、tok/s、Agent 数）

## 时间轴

### 0:00–0:15 · Hook (15s)

**画面**：

- 学生 IDE 截图：满屏红色编译错误 + WA + 时间戳"凌晨 2 点"
- 切到本项目 logo + slogan "AI Coding Coach — 11 个 Agent，主动陪你练算法"

**解说**：

> 凌晨 2 点，刷算法的同学第 4 次 Wrong Answer。等老师等不到，问 ChatGPT 它直接给完整 AC——这不叫学，叫抄。我们做了一个不同的东西：**11 个 AI Agent 主动陪伴你**，会教，会等，会复习，会规划。

---

### 0:15–0:45 · 30 秒上手 (30s)

**画面**：

- 打开 chrome 新标签 → 输入项目地址
- 中央浮起 QuickSetupCard："输入 API key 即可开始"
- 选 DeepSeek chip → 粘贴 API key → 点「保存并测试」
- 0:30 提示成功 → 主界面显示示例题"两数之和"

**解说**：

> 打开浏览器，复制 API key 到中央这个卡片，点保存——**30 秒，进入主界面**。不需要装环境、不需要注册账号、不需要配 endpoint。**默认用 DeepSeek，但 OpenAI / MiniMax / 本地 Ollama 都支持，自动适配。**

---

### 0:45–1:30 · 第一次 AnalyzeCode（看路由 + 看本地 Agent）(45s)

**画面**：

- 写一段有 bug 的 Two Sum (n²)
- 编辑器右下角 Coach 浮卡：等待 1.2s → 弹出分析结果
- **画面同时**：右上角浮起小 chip "⚡ 本地 (代码 < 1500 字符)"
- 镜头特写 Coach 浮卡的内容：line 14 双重循环 → O(n²) → 建议 unordered_map
- B-roll：切到右侧 AgentTracePanel，看到 3 行 trace

**解说**：

> 我写一个有 bug 的 Two Sum。Coach 自动分析——注意，**右上角这个 ⚡ 表示请求走的是本地 1B 模型 sam:latest**。代码不长，简单题，本地模型 500ms 出结果，**代码不出本机，零 token 费**。同样的请求，复杂题或长代码会自动切到云端 DeepSeek。这就是项目的智能路由层——**该快的快，该深的深**。

---

### 1:30–2:30 · Escalation（连续失败触发 P3）(60s)

**画面**：

- 故意保持 bug，点 "提交"
- SubmitResultModal 选 WA → 提交
- 修了一点点（仍有 bug） → 提交 WA → 再 → WA
- 到第 3 次 WA 时 AnalyzeCode 出来的结果**明显更详细**：
  - 标题改成 "🔄 已 3 次失败，启用深度诊断"
  - 内容：根因分析 + 设计模式建议 + 类似题推荐
- 镜头特写：Trace Panel 出现 "AnalyzeCode (escalated)" 这一行

**解说**：

> 我故意改了一点点没改对，又错了。第 3 次错——**Coach 自动升级了 prompt**。注意这次的反馈不只是「这行错了」，而是 **「你似乎对 hash 表的使用场景理解不深，建议重做 LeetCode 1 / 167 / 653 这 3 道题」**。这就是项目的 escalation 机制：用一个失败计数器决定何时进入「深度教学」模式。**这是 Agent 的 Sense → Decide → Act 循环最直接的体现**。

---

### 2:30–3:45 · DailyPlan 编排链（multi-agent 真协作）(75s)

**画面**：

- 触发场景：刷新页面，模拟"今天首次开 app"
- 中央顶部浮起 DailyPlanCard：先是 spinner "🤖 学习规划 Agent 正在编排…"
- **同步切到右侧 AgentTracePanel 全屏特写**，逐条出现：
  - `[12:00:00] 🤖 学习规划 Agent 启动 (3 步编排)`
  - `[12:00:00] [1/3] 学情诊断 Agent · 输入 (近期错题 4 条 / 7 天 18 次提交 / AC率 56%)`
  - `[12:00:03] [1/3] 学情诊断 Agent · 输出 (薄弱: DP / 滑动窗口 · 强项: 贪心)`
  - `[12:00:03] [2/3] 题目筛选 Agent (本地) · 输出 (新题 3 道 / 复习 2 道)`
  - `[12:00:08] [3/3] 计划编排 Agent · 输出 (今日重点击破滑动窗口)`
  - `[12:00:08] 🤖 编排完成`
- 切回 DailyPlanCard，看到完整今日计划：
  - 1. [复习] LeetCode 3 (你曾在第 28 行写错滑动窗口边界)
  - 2. [新题] LeetCode 76 (相同模板，难度 +1)
  - 3. [概念] 复习 hash 表 + 双指针组合
- 点「接受并开始」 → 卡片折叠成进度条

**解说**：

> **这是项目最核心的创新**。每天首次开 app，3 个 AI Agent 自动协作生成今日学习计划。看右边 trace panel——**第 1 个 Agent 诊断你的薄弱点是 DP 和滑动窗口；第 2 个 Agent 是本地纯逻辑 Agent，不调 LLM 直接打分筛题；第 3 个 Agent 把诊断和候选编排成 3 步学习路径**。
>
> 注意 **第 2 个 Agent 不调 LLM**——这是项目的独特设计：「Agent」≠「都得用 LLM」，本地评分函数也是 Agent，省 token 又稳定。
>
> 这不是 prompt chain，**这是 agent graph**：每一步都能独立失败、独立中断。**前一个的输出严格是后一个的输入。这是 multi-agent 协作的硬证据**。

---

### 3:45–4:15 · 长期价值（错题本 + 主动复习 + OJ 桥）(30s)

**画面**：

- 切到 sidebar 错题本 tab，看到累积的错题列表（带知识点标签 + 复习状态）
- 切到下一天 → DailyReviewCard 自动浮起："你 3 天前在『最长上升子序列』错过，今天还能想起吗？"
- 切到油猴脚本演示：在 educoder 上点提交 → 我的项目右下角同步出现"已收到提交结果，记录到错题本"

**解说**：

> 项目的状态层是真持久化的。**今天的错题，明天的计划，下周的复习推送——一切都连起来**。还有油猴脚本桥接 educoder 和学校 OJ，**评测结果自动进错题本**，无缝接入现有学习流程。

---

### 4:15–4:50 · 杀手镜头 ×4（创新性密度最高） (35s)

**画面节奏：每 8 秒切一个杀手镜头**

#### 4:15–4:23 · 飞行模式（剧场感）
- 鼠标 hover 到 TopBar 上的 ✈ 按钮 → 点击
- 全 UI 浮动出 "✈ 飞行模式 · ⚡ 本地" 红色 chip
- 立刻打一段新代码 → AnalyzeCode 仍正常出结果（路由 chip 显示"⚡ 离线本地"）

**解说**：

> 我现在拔网线 — 看，**点这个飞机图标，进入飞行模式**。注意 AI 仍然能批注代码，因为路由器自动切到本地 1B 模型。**这就是为什么我们的项目不是 ChatGPT 套壳**。

#### 4:23–4:31 · 费曼反向教学（创新性主打）
- 点击 TopBar 上紫色 🧠 "费曼" 按钮 → modal 浮起
- 用户输入："这道两数之和我用哈希表，遍历的时候查 t-a[i]"
- AI 学生回应："等等你说的'哈希表'是字典对吗？为什么要用它而不是排序？"
- 切到 trace panel 看到 `Feynman/Student` 的 trace

**解说**：

> 费曼模式 — 你给 AI 讲题，AI 装菜鸟提问。**这种"反向"是评委最关心的'真创新'**。最后 AI 评委会给清晰度 / 逻辑 / 准确性 3 维度评分。

#### 4:31–4:39 · Agent Graph 视图（可观测性升级）
- 切到 trace panel 头部 → 点 Network 图标
- 13 个 Agent 节点按 5 个集群展示
- 触发一次 AnalyzeCode → 看到 AnalyzeCode 节点 + AstDiff 节点同时**绿色脉冲**

**解说**：

> Trace 不只有时间线 — 切到拓扑图，**13 个 Agent 实时高亮谁在跑**。本地 Agent 用黄色边框标记。这是业界推的 Agent observability 在教育产品的实现。

#### 4:39–4:47 · AST-Light + Dashboard
- 切到 Dashboard 视图
- 看到 AnalyzeCode ×3 / AstDiff ×3（次数对齐）/ DailyPlan/Selector ×1（本地标记）
- 切到一段 n² 暴力代码 → AstDiff 提示"嵌套循环深度 2 · 复杂度估计 O(n²)"

**解说**：

> Dashboard 显示每个 Agent 的调用次数、延迟、token 消耗——**LLM 不再瞎猜复杂度**：本地 AST 启发式 Agent 先提取结构特征，作为客观信号喂给 LLM。

#### 4:47–4:50 · 一句话定调
**画面**：切到对比表

| | ChatGPT 套壳 | **本项目** |
|---|---|---|
| Agent | 1 | **13** |
| 真协作 | 0 | **5** (DailyPlan ×3 + Feynman ×2) |
| 离线可用 | ✗ | **✓** |
| 可观测视图 | 0 | **3** |

**解说**：

> Agent 数从 1 到 13，真协作从 0 到 5，离线可用、可观测、本地工具型 Agent —— **这不是优化，这是范式不同**。

## 录制 Checklist

### 录前

- [ ] **数据准备**：错题本里至少 4 条不同知识点的错题（DP / 贪心 / 滑动窗口 / 图论）
- [ ] **localStorage 清空 dailyPlan key**：让 demo 时能从 0 开始触发编排
- [ ] **API key 用临时账号**：录像里不要漏出真 key，遮挡或后期模糊
- [ ] **网络环境**：保证云端 LLM 5s 内 TTFT，否则 demo 节奏会塌
- [ ] **后台关闭**：Slack / 微信 / 邮件通知全部静音
- [ ] **录屏软件**：OBS Studio (CBR 8000kbps + AAC 192) 或 ScreenFlow

### 录中

- [ ] **故意写错**：Two Sum 的 n² bug 必须明显（双重循环），方便 Coach 一眼看出
- [ ] **escalation 触发**：第 3 次必须真的触发，不要用假数据
- [ ] **DailyPlan 重新规划**：录之前点「重新规划」一次预热，避免冷启动让 Trace 慢
- [ ] **关键时刻别快进**：Trace Panel 出现新 entry 时停留 1–2 秒让评委看清
- [ ] **解说同步**：每段录完先听一遍，画面和解说不能错位

### 录后

- [ ] **加字幕**：每段都打**双行**字幕
- [ ] **关键数字打 chyron**：300ms TTFT / 100% 命中率 / 11 个 Agent / 3 子 Agent / 7 件主动行为
- [ ] **架构图静态时间 ≥ 4s**：让评委读完
- [ ] **背景音乐**：用 lofi 风格或纯 SFX 强调动作（点击、过渡声），别盖过解说
- [ ] **导出**：1080p60 + H.264 high + AAC 256 + 总码率 12 Mbps

## 不要做的事

- ❌ 别讲技术细节超 30s（评委会走神）
- ❌ 别用 PPT 大段文字（评委不会读）
- ❌ 别在动画上堆特效（朴素 spring 进入即可）
- ❌ 别说「我做了 X 行代码」（没人 care 行数）
- ❌ 别讲未来规划超 15s（评委只看现在能跑的）
- ❌ 别在 demo 里露 API key / 邮箱 / 真名 / 群聊截图
